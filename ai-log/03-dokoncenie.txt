  **1. Medium (the most visible issue): open redirect in `/r` that gets past
  `sameOriginUrl`**
  - **Where:** `apps/api/src/common/http.ts:16-24` and
  `apps/api/src/pipeline/links.controller.ts:30-34`
  - **Exploit:** `GET /api/r?to=/.//evil.com` (or
  `?to=https://<site>//evil.com`) parses to the site's own origin with pathname
  `//evil.com`. The controller then sends `Location:
  //evil.com?utm_source=email&utm_medium=nurture`, which the browser treats as a
  protocol-relative URL. That is a phishing redirect on the trusted e-mail link
  domain. I checked the URL parsing in Node. The test lists in
  `test/http.test.ts:8` and `test/api.test.ts:159` don't include this case. The
  code comments claim "no open redirect".
  - **Fix:** After parsing, reject or collapse a pathname that starts with `//`
  (e.g. `if (u.pathname.startsWith('//')) return new URL('/', origin)`), or
  allow only a list of known paths. Add `/.//evil.com` to the tests.

  **2. Medium: if `NODE_ENV` is missing, all three guards open**
  - **Where:** `apps/api/src/config/env.ts:5` defaults `NODE_ENV` to
  `'development'`. Three guards trust that value:
    - `AdminGuard` (`admin/admin.guard.ts:16-17`) lets everyone in when
  `ADMIN_TOKEN` is unset. That exposes PII, the CSV export, manual handoff and
  sending the sequence.
    - `CronGuard` (`pipeline/cron.guard.ts:15`) opens.
    - `OriginGuard` (`common/origin.guard.ts:23`) is skipped entirely.
  - **Scenario:** Someone runs `node apps/api/dist/main.js` on a VM or another
  PaaS without `NODE_ENV` and forgets `ADMIN_TOKEN`, and admin is public.

  `NODE_ENV=production`, and Vercel normally sets it too (worth confirming in
  the function's env).

  code contradicts.

  explicitly). Or require `ADMIN_TOKEN` and `CRON_SECRET` unless `NODE_ENV ===
  'development'` is set explicitly.

  **3. Medium: the per-IP rate limits can be bypassed**
  - **Where:** `apps/api/src/app.setup.ts:8` sets `trust proxy: true`, so
  `req.ip` is the left-most `X-Forwarded-For` value, which the client controls.

  through the Next proxy to get separate IP buckets.
